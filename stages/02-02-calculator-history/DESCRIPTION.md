# Калькулятор с историей: полное описание проекта

Документ описывает фактически реализованное приложение из каталога `02-calculator-history`. Источником истины являются текущие `App.js`, `src/calculator-history.js`, тесты и конфигурация проекта. Примеры ниже соответствуют существующему поведению и не предполагают скрытой серверной части или постоянного хранилища.

## 1. Карточка проекта

| Поле | Значение |
|---|---|
| Русское название | Калькулятор с историей |
| Название на экране | `Calculator History` |
| Тип | Одноэкранное учебное мобильное приложение React Native под управлением Expo |
| Назначение | Сложить или вычесть два введённых числа и сохранить каждое успешное вычисление в хронологической истории |
| Пакет npm | `react-native-homework-calculator-history`, версия `1.0.0` |
| Expo name / slug | `Calculator History` / `calculator-history` |

| Требование к Node.js | `>=20.19.4` |

| Хранение данных | Только память текущего экземпляра приложения |

Интерфейс состоит из карточки вычисления и карточки истории. В первой находятся два управляемых поля, две кнопки, строка ошибки и строка результата. Во второй сначала показано `No calculations yet.`, а после первого успеха — `FlatList` с выражениями.

## 2. Условие задания и точный перевод

**Оригинальная формулировка:**  
**Extend your Calculator app from the assignment 1: Add FlatList component that shows the calculation history. Note! Data is not saved persistently. When the app is restarted the history is cleared.**

**Точный перевод:**  
**Расширьте своё приложение «Калькулятор» из задания 1: добавьте компонент FlatList, который показывает историю вычислений. Примечание! Данные не сохраняются постоянно. При перезапуске приложения история очищается.**

В реализованной версии условие конкретизировано так:

1. Есть ровно два текстовых поля: `First number` и `Second number`.
2. Кнопка `+` выполняет сложение, кнопка `-` — вычитание.
3. Успех отображается как `Result: <число>`.
4. Каждое успешное вычисление добавляется в конец истории в форме `первое операция второе = результат`.
5. История выводится через `FlatList` и сохраняет порядок нажатий.
6. Одинаковые выражения разрешены и получают разные локальные идентификаторы `history-1`, `history-2` и далее.
7. Пустой, синтаксически неверный или бесконечный ввод не создаёт запись.
8. Переполнение результата не создаёт запись.
9. Ошибка новой попытки не удаляет предыдущий успешный результат.
10. Полный перезапуск приложения очищает историю, потому что постоянное хранилище не входит в условие.

## 3. Результаты обучения

После разбора и воспроизведения проекта ученица сможет:

1. Объяснить разницу между текстом поля и числом, полученным после валидации.
2. Создать управляемый `TextInput`, связав `value` со state и `onChangeText` с setter-функцией.
3. Передать кнопке функцию события, не вызывая обработчик во время рендера.
4. Разделить интерфейсный слой и чистые функции предметной логики.
5. Проверить десятичное число с точкой или запятой и отклонить пустую строку, экспоненциальную, шестнадцатеричную и смешанную запись.
6. Обновить массив state без мутации через функциональную форму setter.
7. Отобразить хронологическую историю через `FlatList`.
8. Обосновать, почему стабильный `id` подходит для `keyExtractor`, а текст выражения — нет.
9. Выбрать `useRef` для счётчика, изменение которого не должно само вызывать рендер.
10. Добавить доступные имена полям и списку, а динамическим сообщениям — вежливое объявление изменений.
11. Проверить чистую логику модульными тестами и полный пользовательский сценарий компонентными тестами.
12. Устно защитить архитектуру и поток данных на русском и английском языках.

Измеримый результат: ученица без подсказки демонстрирует три успешных операции, одну ошибочную попытку, объясняет пять переменных state и получает не менее 8 баллов по рубрике из `METHODICAL_GUIDE.md`.

## 4. Функциональные критерии

| № | Дано | Действие | Ожидаемый результат |
|---:|---|---|---|
| 1 | Приложение только запущено | Ничего не вводить | Видны `Result:` и `No calculations yet.`; текст ошибки пуст |
| 2 | `firstInput = '36'`, `secondInput = '5'` | Нажать `+` | `Result: 41`; первая строка истории `36 + 5 = 41` |
| 3 | После критерия 2 | Ввести `69` и `25`, нажать `+` | Вторая строка `69 + 25 = 94` расположена после первой |
| 4 | После критерия 3 | Ввести `78` и `69`, нажать `-` | `Result: 9`; третья строка `78 - 69 = 9` |
| 5 | Поля содержат `2,5` и `1.25` | Нажать `+` | `Result: 3.75`; запятая корректно нормализована |
| 6 | Поля содержат `-.5` и `+12` | Нажать поддерживаемую операцию | Оба значения принимаются как конечные числа |
| 7 | Одна операция уже выполнена | Повторить то же выражение | Появляются две строки с одинаковым `expression`, но разными `id` |
| 8 | Второе поле пусто | Нажать любую кнопку | `Enter a valid number.`; история, последний результат и следующий id не меняются |
| 9 | Поле содержит `Infinity`, `1e2`, `0x10`, `1,2.3` или `--2` | Нажать любую кнопку | `Enter a valid number.`; новая запись отсутствует |
| 10 | Оба входа конечны, но их сумма переполняет диапазон `Number` | Нажать `+` | `Result is outside the supported number range.`; прежние успешные данные сохранены |
| 11 | После ошибки введены корректные числа | Нажать кнопку | Ошибка очищается, результат и история обновляются, id продолжает последовательность без пропуска |
| 12 | История содержит несколько записей | Полностью остановить и запустить приложение | История снова пуста |

Нефункциональные критерии:

- интерфейс ограничен шириной `420` и остаётся читаемым на широком экране;
- поля имеют видимые подписи, placeholder и доступные имена;
- изменения результата и ошибки отмечены `accessibilityLiveRegion="polite"`;
- список использует стабильные строковые ключи;
- предметные функции не зависят от React Native и проверяются отдельно;
- существующий state обновляется неизменяемо.

## 6. Архитектура и ответственности

Архитектура намеренно мала и разделена по характеру ответственности.

| Слой | Элементы | Ответственность | Чего слой не делает |
|---|---|---|---|
| Представление | `View`, `Text`, `TextInput`, `Button`, `FlatList`, `StatusBar` | Строит экран и связывает props с данными | Не разбирает числовой синтаксис самостоятельно |
| Оркестрация | `App` и `handleCalculation` | Читает state, запускает расчёт, выбирает ветку ошибки/успеха, обновляет UI | Не содержит регулярное выражение и правила форматирования |
| Предметная логика | Функции из `src/calculator-history.js` | Проверяет, вычисляет, форматирует и создаёт новые структуры данных | Не обращается к React, нативному UI или хранилищу |
| Автотесты | Два файла из `__tests__` | Фиксируют контракт функций и поведение пользовательского сценария | Не заменяют проверку на реальном устройстве |
| Конфигурация | `package.json` и `app.json` | Определяет версии, команды и Expo-настройки | Не хранит state приложения |

Ответственности функций:

- `parseNumberInput(text)` — синтаксическая и числовая проверка одного поля;
- `calculateValues(firstText, secondText, operation)` — проверка обоих полей и одна операция;
- `formatNumber(value)` — отображаемая строка с округлением простого двоичного шума;
- `createHistoryEntry(id, first, operation, second, result)` — объект записи с готовым выражением;
- `getHistoryEntryKey(entry)` — стабильный ключ `entry.id`;
- `appendHistory(history, entry)` — новый массив с записью в конце;
- `handleCalculation(operation)` — единственная точка перехода от события кнопки к обновлению state.

Такое разделение позволяет тестировать математические правила без рендера и отдельно проверять, что интерфейс правильно вызывает эти правила.

## 7. Модель state и ref

### 7.1. Переменные state

| Имя | Начальное значение | Тип в текущей модели | Кто читает | Кто изменяет | Назначение |
|---|---|---|---|---|---|
| `firstInput` | `''` | Строка | `handleCalculation`, первый `TextInput.value` | `setFirstInput` через `onChangeText` | Точный текст первого поля |
| `secondInput` | `''` | Строка | `handleCalculation`, второй `TextInput.value` | `setSecondInput` через `onChangeText` | Точный текст второго поля |
| `resultMessage` | `'Result:'` | Строка | `Text` с `testID="result-message"` | `setResultMessage` после успеха | Последний успешный результат |
| `errorMessage` | `''` | Строка | `Text` с `testID="error-message"` | `setErrorMessage` в обеих ветках | Ошибка последней попытки или пустая строка |
| `history` | `[]` | Массив объектов `{ id, expression }` | Условный рендер и `FlatList.data` | `setHistory` после успеха | Успешные вычисления в порядке выполнения |

### 7.2. Ref, который не является state

`nextHistoryIdRef` создаётся как `useRef(1)`. Текущее число доступно через `nextHistoryIdRef.current`. Оно:

- сохраняется между рендерами;
- не выводится напрямую;
- увеличивается только после успешного `createHistoryEntry`;
- не меняется в ветке ошибки;
- не вызывает дополнительный рендер при изменении.

### 7.3. Инварианты

1. `history.length` равна количеству успешных нажатий с момента запуска.
2. Все `history[i].id` уникальны в рамках текущего запуска.
3. Порядок элементов массива совпадает с порядком успешных событий.
4. Ошибка не меняет `resultMessage`, `history` и `nextHistoryIdRef.current`.
5. Успех очищает `errorMessage`.
6. Поля не очищаются автоматически ни после успеха, ни после ошибки.
7. Элементы истории после создания не редактируются.

## 8. Поток данных и событий

### 8.1. Управляемый ввод

```text
ввод символа
→ TextInput вызывает onChangeText(nextText)
→ setFirstInput(nextText) или setSecondInput(nextText)
→ React выполняет новый рендер
→ value поля получает актуальную строку из state
```

Строковый state важен: он способен хранить пустой ввод и промежуточную запись, пока пользователь ещё печатает. Преобразование в число откладывается до нажатия кнопки.

### 8.2. Успешная операция

```text
нажатие + или -
→ onPress передаёт '+' или '-' в handleCalculation
→ calculateValues проверяет оба текста и вычисляет value
→ Number(...) получает нормализованные first и second для истории
→ createHistoryEntry создаёт id и expression
→ nextHistoryIdRef.current увеличивается
→ setHistory(previous => appendHistory(previous, entry))
→ errorMessage становится ''
→ resultMessage становится 'Result: <форматированное значение>'
→ React показывает результат и FlatList с новым массивом
```

### 8.3. Ошибочная операция

```text
нажатие + или -
→ calculateValues возвращает { ok: false, error }
→ setErrorMessage(calculation.error)
→ ранний return
→ результат, история и счётчик id остаются прежними
```

### 8.4. Почему используется функциональный setter

`setHistory((previous) => appendHistory(previous, entry))` получает актуальную ожидающую версию истории. Это особенно важно, когда несколько обновлений могут попасть в очередь. `appendHistory` возвращает новый массив `[...history, entry]`, поэтому ссылка `data` меняется и `FlatList` получает видимое обновление.

## 9. Алгоритмы

### 9.1. `parseNumberInput(text)`

1. Удалить пробелы по краям через `trim()`.
2. Проверить строку регулярным выражением `/^[+-]?(?:\d+(?:[.,]\d+)?|[.,]\d+)$/`.
3. При несоответствии вернуть `{ ok: false, error: 'Enter a valid number.' }`.
4. Заменить первую допустимую запятую точкой.
5. Преобразовать строку через `Number`.
6. Проверить `Number.isFinite(value)`.
7. Вернуть `{ ok: true, value }`.

Регулярное выражение разрешает необязательный знак, целую часть с необязательной дробной частью либо дробь без цифры до разделителя. Поэтому `+12`, `2,5`, `.5` и `-.5` допустимы, а `2.`, `1e2`, `0x10` и `1,2.3` — нет.

### 9.2. `calculateValues(firstText, secondText, operation)`

1. Вызвать `parseNumberInput` для первого текста.
2. Вызвать `parseNumberInput` для второго текста.
3. Сначала проверить результат разбора первого поля и вернуть его ошибку,
   если `first.ok === false`.
4. Затем проверить результат разбора второго поля и вернуть его ошибку,
   если `second.ok === false`.
5. Если `operation === '+'`, сложить; иначе выполнить вычитание.
6. Проверить конечность результата.
7. При переполнении вернуть `Result is outside the supported number range.`.
8. Иначе вернуть `{ ok: true, value }`.

Компонент `App` передаёт только `'+'` и `'-'`. Отдельной ветки для произвольной операции нет, поскольку внешний интерфейс функции в этом проекте ограничен двумя кнопками.

### 9.3. `formatNumber(value)`

Алгоритм `String(Number(value.toFixed(10)))` округляет значение до десяти знаков после запятой, затем снова превращает его в число и строку. Это:

- превращает `0.30000000000000004` в `0.3`;
- не добавляет `.0` целому числу;
- убирает конечные незначащие нули;
- не является произвольной десятичной арифметикой высокой точности.

### 9.4. История

`createHistoryEntry` форматирует оба операнда и результат, затем строит `expression`. `appendHistory` добавляет объект в конец нового массива. `getHistoryEntryKey` возвращает `entry.id`, поэтому две одинаковые строки остаются разными элементами списка.

## 10. Валидация и обработка ошибок

| Ситуация | Результат проверки | Сообщение | Что меняется | Что сохраняется |
|---|---|---|---|---|
| Пустая строка или только пробелы | Ошибка синтаксиса | `Enter a valid number.` | Только `errorMessage` | Поля, результат, история, id |
| Буквы, `Infinity`, `NaN` | Ошибка синтаксиса | `Enter a valid number.` | Только `errorMessage` | Последний успех и история |
| Экспонента `1e2` | Отклоняется текущим форматом | `Enter a valid number.` | Только `errorMessage` | Последний успех и история |
| Шестнадцатеричное `0x10` | Отклоняется текущим форматом | `Enter a valid number.` | Только `errorMessage` | Последний успех и история |
| Смешанные разделители `1,2.3` | Ошибка синтаксиса | `Enter a valid number.` | Только `errorMessage` | Последний успех и история |
| Первый текст неверен | Оба текста разбираются, затем первой проверяется ошибка `first` | `Enter a valid number.` | Только `errorMessage` | Результат разбора второго поля не используется; запись не создаётся |
| Второй текст неверен | Оба текста разбираются; `first` успешен, затем возвращается ошибка `second` | `Enter a valid number.` | Только `errorMessage` | Успешная запись не создаётся |
| Оба числа конечны, результат бесконечен | Ошибка диапазона | `Result is outside the supported number range.` | Только `errorMessage` | `resultMessage`, `history`, следующий id |
| Следующая попытка корректна | Успех | Ошибка очищается | История, результат, id, `errorMessage` | Тексты полей |

`keyboardType="numeric"` только просит платформу показать подходящую клавиатуру. Это не защита данных: физическая клавиатура, вставка текста и платформенные различия всё равно требуют `parseNumberInput`.

В текущем UI нет исключений, которые показываются пользователю как stack trace. Все ожидаемые ошибки представлены объектами результата с полем `ok`.

- Android Studio, Android SDK и хотя бы одно виртуальное устройство Android;
- при работе с физическим телефоном — Expo Go, совместимый с SDK 54.

Порядок первого запуска:

1. Откройте Android Studio, запустите эмулятор и дождитесь домашнего экрана Android.
2. Откройте PowerShell в каталоге проекта.
3. Проверьте среду:

   ```powershell
   node --version
   npm --version
   Get-Command node,npm | Select-Object Name,Source
   ```

4. Установите строго зафиксированные зависимости:

   ```powershell
   npm ci
   ```

5. При желании проверьте согласованность Expo-конфигурации:

   ```powershell
   npx expo-doctor
   ```

6. Запустите Metro:

   ```powershell
   npm run start
   ```

7. В терминальном меню Expo нажмите `a`. Альтернативная команда, когда эмулятор уже работает:

   ```powershell
   npm run android
   ```

Для физического Android-устройства компьютер и телефон обычно должны быть в одной сети; откройте Expo Go и отсканируйте QR-код Metro. При проблеме с устаревшим кешем остановите Metro через `Ctrl+C` и выполните `npx expo start --clear`.


### 11.3. Повторный запуск и диагностика среды

- При неизменных `package-lock.json` и `node_modules` обычно достаточно `npm run start`.
- После удаления `node_modules` снова используйте `npm ci`.
- Если `node --version` ниже `20.19.4`, обновите Node.js и полностью перезапустите терминал.
- Если Android не открывается, сначала убедитесь, что эмулятор загрузился и виден инструментам Android.
- Если iOS не открывается, запустите Simulator вручную и проверьте выбранные Command Line Tools в Xcode.
- Если порт занят, согласитесь на свободный порт или остановите предыдущий Metro.
- Если Expo Go сообщает о несовместимом SDK, установите совместимую с SDK 54 версию клиента.

## 12. Тестирование и приёмка

### 12.1. Автоматические команды

```powershell
npm test -- --runInBand
npx expo-doctor
```

Скрипт `npm test` уже включает `--watchAll=false`, поэтому процесс завершается после прогона. `--runInBand` делает порядок вывода предсказуемым в учебной среде.

### 12.2. Что покрывает текущий набор тестов

| Набор | Проверки |
|---|---|
| `calculator-history.test.js` | Точка и запятая, знаки, `-.5`, пустота, бесконечность, запрещённые нотации, `+` и `-`, переполнение, округление, выражение истории, неизменяемость массива, дубликаты и отсутствие кандидата при ошибке |
| `App.test.js` | Пустая история, управляемый ввод, обе кнопки, хронологические `data`, ключи `history-1...`, последний результат, переполнение без изменения истории и id, восстановление после ошибки |

Тесты намеренно ищут:

- `First number` и `Second number` через `accessibilityLabel`;
- `Calculation history` и `Empty history message` через `accessibilityLabel`;
- `error-message` и `result-message` через `testID`;
- кнопки по роли `button` и именам `+` / `-`.

У динамических сообщений нет искусственного `accessibilityLabel`: тесты отдельно закрепляют это свойство, чтобы экранный диктор получал актуальное текстовое содержимое.

### 12.3. Ручной приёмочный сценарий

1. Запустить приложение и подтвердить `No calculations yet.`.
2. Выполнить `36 + 5` и увидеть `Result: 41`.
3. Выполнить `69 + 25`; убедиться, что `69 + 25 = 94` ниже первой записи.
4. Выполнить `78 - 69`; убедиться, что `78 - 69 = 9` — третья запись.
5. Повторить `78 - 69` и проверить две одинаковые строки без предупреждения о ключах.
6. Ввести `2,5` и `1.25`, получить `3.75`.
7. Очистить второе поле и нажать `+`: увидеть `Enter a valid number.` и неизменный прошлый результат.
8. После ошибки выполнить корректную операцию и убедиться, что ошибка исчезла, а id не пропущен.
9. Проверить фокус и чтение полей экранным диктором; на Android проверить объявление изменившихся результата и ошибки.
10. Полностью перезапустить приложение и подтвердить пустую историю.

Приёмка успешна, если автоматические проверки завершаются без ошибок и все десять ручных пунктов воспроизводятся на целевой платформе.

## 13. Ограничения и осознанные упрощения

1. Поддерживаются только `+` и `-`; умножения, деления и приоритета операций нет.
2. История не сохраняется в AsyncStorage, файле, базе данных или облаке.
3. Нет кнопок очистки, удаления и редактирования истории.
4. Нет отмены операции и перехода к выбранной записи.
5. Все вычисления используют JavaScript `Number`, то есть двоичное число двойной точности, а не точную финансовую десятичную арифметику.
6. `formatNumber` округляет до десяти дробных знаков; очень точные хвосты намеренно сокращаются.
7. Экспоненциальная и шестнадцатеричная формы ввода запрещены, хотя JavaScript `Number` умеет их разбирать.
8. Запись `2.` запрещена; нужно ввести `2` или `2.0`.
9. `keyboardType="numeric"` не гарантирует одинаковый набор клавиш на всех платформах и не заменяет валидацию.
10. При неверности обоих полей отображается общее сообщение; конкретное поле визуально не подсвечивается.
11. `accessibilityLiveRegion` относится прежде всего к Android; отдельного iOS-механизма объявления в текущем коде нет.
12. Интерфейс одноязычный, хотя защита проекта предусмотрена на русском и английском.
13. Экран не использует навигационную библиотеку: всё приложение — один компонентный маршрут.
14. Светлая тема зафиксирована в `app.json`; переключения на тёмную тему нет.
15. Максимальная ширина основного содержимого равна `420`, поэтому планшет использует центрированную узкую колонку.

Эти ограничения соответствуют учебной цели: показать state, события, чистую логику, список и тестирование без лишней инфраструктуры.

## 14. Защита проекта на русском и английском

### 14.1. Краткая демонстрация

**Русский вариант:**  
«Это одноэкранный калькулятор React Native. Два управляемых поля хранят текст в `firstInput` и `secondInput`. По нажатию `+` или `-` обработчик сначала вызывает чистую валидацию. Успешная операция обновляет `resultMessage` и добавляет объект `{ id, expression }` в `history`. Ошибка меняет только `errorMessage`, поэтому последний корректный результат, история и следующий id сохраняются. `FlatList` показывает записи в порядке выполнения, а `nextHistoryIdRef` выдаёт стабильные ключи даже одинаковым выражениям».

**English version:**  
“This is a single-screen React Native calculator. Two controlled inputs keep their text in `firstInput` and `secondInput`. When the user presses `+` or `-`, the handler calls pure validation first. A successful operation updates `resultMessage` and appends an `{ id, expression }` object to `history`. An invalid attempt updates only `errorMessage`, so the last valid result, the history, and the next id stay unchanged. `FlatList` renders entries in chronological order, and `nextHistoryIdRef` provides stable keys even for duplicate expressions.”

### 14.2. Вопросы и модельные ответы

| Вопрос | Полный ответ по-русски | Model answer in English |
|---|---|---|
| Почему ввод хранится строкой? | `TextInput` выдаёт текст. Строка сохраняет пустое и незаконченное значение; преобразование выполняется только при осознанном нажатии кнопки. | “`TextInput` emits text. A string can represent empty and incomplete input, so I convert it only when the user presses a button.” |
| Почему нельзя использовать `Number(text)` без проверки? | `Number('')` даёт `0`, а некоторые формы вроде экспоненты были бы приняты вопреки заданному формату. Регулярное выражение сначала фиксирует допустимую грамматику. | “`Number('')` becomes zero and JavaScript accepts formats that this task forbids. The regular expression enforces the input grammar first.” |
| Зачем чистые функции вынесены отдельно? | Они не зависят от рендера и платформы, поэтому их проще объяснять, повторно использовать и проверять детерминированными тестами. | “They do not depend on rendering or the platform, so they are easier to reason about and test deterministically.” |
| Почему `history.push` не используется? | `push` меняет существующий массив. React state рассматривается как неизменяемый, поэтому `appendHistory` возвращает новую ссылку. | “`push` mutates the existing array. I return a new array so React receives a new state reference.” |
| Почему setter функциональный? | Следующее значение зависит от предыдущей истории. Функция updater получает актуальную ожидающую версию массива. | “The next history depends on the previous history, so the updater function receives the latest pending array.” |
| Почему текст выражения не является ключом? | Одинаковые вычисления допустимы, поэтому их текст повторяется. Локальный `history-*` id уникален и стабилен. | “Duplicate calculations are allowed, so expression text can repeat. A local `history-*` id stays unique and stable.” |
| Почему id хранится в `useRef`? | Счётчик нужен между рендерами, но сам не отображается. Изменение `current` не создаёт лишний рендер. | “The counter must survive renders, but it is not displayed. Updating `current` does not trigger an extra render.” |
| Что происходит при ошибке? | `calculateValues` возвращает `ok: false`, обработчик задаёт точное сообщение и завершает работу до создания записи и увеличения id. | “`calculateValues` returns `ok: false`, so the handler sets the exact message and returns before creating an entry or incrementing the id.” |
| Почему результат `0.1 + 0.2` показывается как `0.3`? | `formatNumber` округляет до десяти дробных знаков, затем удаляет незначащие нули через повторное преобразование в число. | “`formatNumber` rounds to ten decimal places and then removes insignificant zeros through numeric conversion.” |
| Что исчезнет после перезапуска? | Все пять значений state и ref инициализируются заново, потому что постоянное хранилище не используется. | “All five state values and the ref are initialized again because the app does not use persistent storage.” |

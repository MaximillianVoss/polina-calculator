## 1. Оригинальное требование и перевод

Формулировка со скриншота:

> Extend your Calculator app from the assignment 1:
>
> Add FlatList component that shows the calculation history.
>
> Note! Data is not saved persistently. When the app is restarted the history
> is cleared.

Точный перевод:

> Расширьте приложение Calculator из задания 1: добавьте компонент FlatList,
> который показывает историю вычислений. Обратите внимание: данные не
> сохраняются постоянно. После перезапуска приложения история очищается.

Дополнительные условия: история выводится через `FlatList`, одинаковые выражения разрешены, ошибочный ввод не добавляет запись, а после полного перезапуска история пуста.

## 2. Реализованные критерии

- два управляемых поля с видимыми подписями, placeholder и цифровой клавиатурой;
- кнопки `+` и `-`, результат `Result: ...` и доступное сообщение об ошибке;
- числа с точкой и запятой, например `2,5 + 1.25`;
- история в порядке выполнения: `36 + 5 = 41`, затем `69 + 25 = 94`, затем `78 - 69 = 9`;
- повтор одного выражения создаёт две строки с разными `history-*` id;
- ошибочное вычисление не меняет прежний результат, историю и счётчик id;
- данные хранятся только в памяти текущего запуска.

## 6. Состояние, события и поток данных

`firstInput` и `secondInput` хранят текст полей. `resultMessage` и `errorMessage` управляют обратной связью. `history` содержит объекты `{ id, expression }`, а `nextHistoryIdRef` хранит следующий стабильный id без отдельного рендера.

Поток события: пользователь меняет поля → нажимает кнопку → `handleCalculation` вызывает чистую проверку → при ошибке обновляется только ошибка → при успехе создаётся запись → функциональный `setHistory` получает предыдущий массив и возвращает новый → React повторно отображает результат и `FlatList`.

## 7. Разбор App.js и чистой логики

В `App.js` компонент объявляет state, обработчик вычисления и разметку. Кнопки получают функции `() => handleCalculation('+')` и `() => handleCalculation('-')`, поэтому вычисление не запускается во время рендера. Успешный результат преобразуется в готовую запись, id увеличивается только после проверки.

`src/calculator-history.js` не зависит от React Native:

- `parseNumberInput` обрезает пробелы, заменяет запятую и отклоняет пустоту, `NaN` и бесконечность;
- `calculateValues` складывает или вычитает только два проверенных значения;
- `formatNumber` убирает незначащую дробную часть и простой двоичный шум;
- `createHistoryEntry` готовит строку для списка;
- `appendHistory` возвращает `[...history, entry]`, не меняя исходный массив.

## 8. React и React Native понятия

- **Функциональный компонент** — обычная функция, возвращающая JSX.
- **JSX** — описание интерфейса компонентами `View`, `Text`, `TextInput` и `FlatList`.
- **useState** — хранит данные интерфейса и вызывает повторный рендер после setter.
- **useRef** — сохраняет счётчик между рендерами, но его изменение само не перерисовывает экран.
- **Управляемый ввод** — `value` берётся из state, а `onChangeText` обновляет state.
- **Событие** — `onPress` запускает обработчик только после действия пользователя.
- **Неизменяемое обновление** — новый массив заменяет старый, что делает изменение заметным React.
- **FlatList** — эффективно отображает данные списка; `keyExtractor` возвращает стабильный id.
- **Доступность** — `accessibilityLabel` позволяет тестам и экранному диктору найти назначение элемента.

## 10. Ручной приёмочный чек-лист

1. После запуска виден текст `No calculations yet.`.
2. Ввести `36` и `5`, нажать `+`: результат `Result: 41`, первая строка `36 + 5 = 41`.
3. Ввести `69` и `25`, нажать `+`: ниже появляется `69 + 25 = 94`.
4. Ввести `78` и `69`, нажать `-`: третья строка `78 - 69 = 9`.
5. Повторить последнюю операцию: появляются две одинаковые строки, приложение не сообщает о дубликате ключа.
6. Очистить второе поле и нажать кнопку: видна `Enter a valid number.`, прежний результат и число строк не меняются.
7. Полностью остановить и снова запустить приложение: снова виден пустой список.

Автоматические проверки не заменяют пункты 1–7 на AVD.

## 11. Диагностика типичных ошибок

- **Неверная версия Node:** одна из двух команд проверки показывает значение ниже `20.19.4` — обновите системный Node.js, затем полностью перезапустите терминал и VS Code.
- **Нет устройства в adb:** `adb devices` не показывает `device` — запустите AVD и дождитесь главного экрана Android.
- **Порт Metro занят:** Expo предлагает другой порт — завершите старый Metro через `Ctrl+C` либо подтвердите свободный порт.
- **Повреждён кеш Metro:** старый интерфейс остаётся после правки — остановите сервер и выполните `npx expo start --clear`.
- **Несовместимый Expo Go:** сообщение о неподдерживаемом SDK — обновите Expo Go до версии с поддержкой SDK 54.
- **Приложение не открылось после `a`:** проверьте, что AVD загрузился, `adb devices` видит его, затем снова нажмите `a` или перезапустите Metro.

Ошибки ученика в коде: `Number('')` даёт 0, поэтому пустота проверяется до преобразования; `history.push(...)` мутирует state; выражение нельзя использовать как ключ, потому что дубликаты допустимы.

## 12. Вопросы преподавателя

1. Почему значения `TextInput` хранятся строками до события кнопки?
2. Почему `setHistory((previous) => ...)` надёжнее прямого изменения массива?
3. Почему `entry.expression` не подходит как ключ?
4. Чем `useRef` отличается от `useState` для счётчика id?
5. Почему ошибочный ввод не должен очищать успешный результат?
6. Что исчезнет после полного перезапуска и почему?

## 13. Краткие ответы

1. Строка сохраняет пустое и незаконченное значение, а проверка выполняется в момент действия.
2. Setter получает актуальный массив и возвращает новый объект, который React может сравнить по ссылке.
3. Два одинаковых вычисления имеют одинаковый текст, но ключи списка должны быть уникальны и стабильны.
4. Изменение `useRef.current` не запускает рендер; счётчик сам по себе не отображается.
5. Ошибка относится к новой попытке ввода и не отменяет уже корректное вычисление.
6. Результат и история исчезнут, потому что AsyncStorage или база данных намеренно не используются.

## 14. Английские формулировки для защиты

- `The input is stored as text until the button event.`
- `I validate both fields before I calculate the result.`
- `FlatList renders the history data.`
- `I create a new array instead of changing the old one.`
- `Each history row has a stable local id, so duplicate expressions are safe.`
- `Invalid input does not add a history entry or replace the last valid result.`
- `The history is kept in memory and a full restart clears it.`

## 15. Необязательные самостоятельные улучшения

После выполнения обязательной версии можно самостоятельно добавить удаление одной записи, кнопку очистки истории или умножение и деление. Для каждой новой операции сначала нужны тесты и явная обработка ошибок. Сохранение между запусками, навигация и сторонние UI-библиотеки не входят в это задание.

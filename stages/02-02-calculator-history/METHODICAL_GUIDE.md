# Методическое руководство: «Калькулятор с историей»

Руководство рассчитано на индивидуальное или парное 90-минутное занятие по готовому проекту React Native. Оно позволяет не только повторить код, но и проверить понимание управляемого ввода, state, событий, чистых функций, неизменяемого списка, доступности и тестов. Все имена и сообщения соответствуют текущей реализации.

## 1. Аудитория и пререквизиты

### Целевая аудитория

- ученица, знакомая с основами JavaScript и впервые или повторно изучающая React Native;
- начинающий разработчик, которому важно связать теорию React с работающим мобильным интерфейсом;
- формат: один преподаватель и одна ученица либо пара учениц;
- рекомендуемый уровень до занятия: умеет читать функции, условия, массивы и объекты, но может ещё путать state, ref и обычную переменную.

### Предметные пререквизиты

Ученица должна узнавать:

- `const`, `let`, функции и `return`;
- строку, число, массив и объект;
- шаблонную строку;
- условие `if` и тернарный оператор;
- методы `trim`, `replace` и `map` на уровне чтения;
- spread-синтаксис `[...history, entry]`;
- импорт и экспорт;
- назначение JSX;
- идею события нажатия.

Знание регулярных выражений целиком не требуется: выражение разбирается по частям на занятии.

### Технические пререквизиты

- Node.js `>=20.19.4` и npm;
- установленные зависимости проекта;
- Expo SDK 54 из локальной зависимости;
- Android-эмулятор, физическое Android-устройство либо iOS Simulator на macOS;
- редактор с подсветкой JavaScript;
- возможность выполнить `npm test -- --runInBand`.

### Критерий готовности к занятию

Ученица может ответить хотя бы на три из пяти вопросов:

1. Что возвращает функция?
2. Чем строка `'2.5'` отличается от числа `2.5`?
3. Почему массив нельзя безопасно менять через `push`, если он лежит в React state?
4. Когда должен выполняться обработчик `onPress`?
5. Для чего элементам списка нужен ключ?

Если ответов меньше трёх, преподаватель добавляет перед занятием 15-минутный повтор JavaScript, не сокращая практику с событиями.

## 5. Входная диагностика

Диагностика занимает семь минут в составе общего тайминга. Важно просить сначала прогноз, а затем объяснение.

| Вопрос преподавателя | Ожидаемый ответ | Если ответа нет |
|---|---|---|
| «Какое значение возвращает `Number('')`?» | `0` | Показать в консоли и спросить, почему одной конверсии недостаточно |
| «Что получает `onChangeText`?» | Новую строку поля | Сравнить с web-событием, где часто читают `event.target.value` |
| «Что произойдёт при `onPress={handleCalculation('+')}`?» | Функция вызовется во время рендера | Нарисовать различие «вызвать сейчас» и «передать функцию» |
| «Что вернёт `[...before, entry]`?» | Новый массив со старыми элементами и `entry` в конце | Показать разные ссылки `before !== after` |
| «Могут ли две записи иметь `expression = '36 + 5 = 41'`?» | Да | Спросить, почему этот текст тогда нельзя брать как уникальный ключ |
| «Запускает ли изменение `ref.current` рендер?» | Нет | Сопоставить с setter из `useState` |
| «Что должно измениться при неверной новой попытке?» | Только `errorMessage` | Вернуться к требованию о сохранении последнего успеха |

Оценка:

- 6–7 верных — можно ускорить объяснение синтаксиса и дать больше самостоятельной практики;
- 3–5 — основной сценарий занятия;
- 0–2 — преподаватель проговаривает каждый переход данных и сокращает количество дополнительных вопросов, но не убирает самостоятельное задание.

## 7. Пошаговое программирование

Раздел задаёт порядок воспроизведения решения в учебной копии. После каждого шага выполняется маленькая проверка, а не набор всего приложения вслепую.

### Шаг 1. Сформулировать контракты чистых функций

До кода записать:

- валидный разбор → `{ ok: true, value }`;
- невалидный разбор → `{ ok: false, error: 'Enter a valid number.' }`;
- вычисление → такой же discriminated result;
- запись истории → `{ id, expression }`;
- добавление → новый массив.

Проверка понимания: ученица объясняет, почему вызывающий код сначала смотрит на `ok`.

### Шаг 2. Реализовать `parseNumberInput`

```js
export function parseNumberInput(text) {
  const trimmed = text.trim();
  const decimalPattern = /^[+-]?(?:\d+(?:[.,]\d+)?|[.,]\d+)$/;
  if (!decimalPattern.test(trimmed)) {
    return { ok: false, error: 'Enter a valid number.' };
  }

  const normalized = trimmed.replace(',', '.');
  const value = Number(normalized);
  if (!Number.isFinite(value)) {
    return { ok: false, error: 'Enter a valid number.' };
  }
  return { ok: true, value };
}
```

Контрольные примеры: `' 2,5 ' → 2.5`, `'-.5' → -0.5`, `'' → error`, `'1e2' → error`.

### Шаг 3. Реализовать вычисление

```js
export function calculateValues(firstText, secondText, operation) {
  const first = parseNumberInput(firstText);
  const second = parseNumberInput(secondText);
  if (!first.ok) return first;
  if (!second.ok) return second;
  const value = operation === '+' ? first.value + second.value : first.value - second.value;
  if (!Number.isFinite(value)) {
    return { ok: false, error: 'Result is outside the supported number range.' };
  }
  return { ok: true, value };
}
```

Преподаватель просит указать, почему проверка результата нужна отдельно от проверки двух операндов: сумма двух конечных очень больших чисел может стать `Infinity`.

### Шаг 4. Добавить формат и неизменяемую историю

```js
export function formatNumber(value) {
  return String(Number(value.toFixed(10)));
}

export function createHistoryEntry(id, first, operation, second, result) {
  return {
    id,
    expression: `${formatNumber(first)} ${operation} ${formatNumber(second)} = ${formatNumber(result)}`,
  };
}

export function getHistoryEntryKey(entry) {
  return entry.id;
}

export function appendHistory(history, entry) {
  return [...history, entry];
}
```

Микропроверка: `formatNumber(0.1 + 0.2)` должно дать `'0.3'`, а исходный массив после `appendHistory` должен остаться равным прежнему.

### Шаг 6. Собрать обработчик

Сначала написать ветку ошибки с ранним `return`, затем ветку успеха:

```js
function handleCalculation(operation) {
  const calculation = calculateValues(firstInput, secondInput, operation);
  if (!calculation.ok) {
    setErrorMessage(calculation.error);
    return;
  }

  const first = Number(firstInput.trim().replace(',', '.'));
  const second = Number(secondInput.trim().replace(',', '.'));
  const entry = createHistoryEntry(
    `history-${nextHistoryIdRef.current}`,
    first,
    operation,
    second,
    calculation.value,
  );

  nextHistoryIdRef.current += 1;
  setHistory((previous) => appendHistory(previous, entry));
  setErrorMessage('');
  setResultMessage(`Result: ${formatNumber(calculation.value)}`);
}
```

Микропроверка: при ошибке ученица пальцем проходит до `return` и убеждается, что увеличение id находится ниже.

## 8. Разбор текущего кода

### 8.1. Почему `App.js` остаётся читаемым

`App.js` отвечает только за данные интерфейса и последовательность действий. Регулярное выражение, форматирование и создание массива вынесены. Поэтому `handleCalculation` читается как сценарий:

```text
получить результат проверки
→ завершить при ошибке
→ создать запись
→ увеличить id
→ добавить историю
→ очистить ошибку
→ показать результат
```

### 8.2. Пять state — не дублирование

- `firstInput` и `secondInput` — ввод пользователя;
- `resultMessage` — подтверждённый результат;
- `errorMessage` — состояние последней неудачной попытки;
- `history` — коллекция подтверждённых результатов.

`resultMessage` нельзя безусловно вычислять из полей: пользователь может изменить поле после успеха, но результат должен оставаться последним подтверждённым. `errorMessage` также зависит от события кнопки, а не просто от текущего текста.

### 8.3. Порядок инструкций в `handleCalculation`

| Инструкция | Почему стоит именно здесь |
|---|---|
| `calculateValues(...)` | Нельзя создавать запись до проверки |
| `if (!calculation.ok)` | Отделяет отрицательный контракт |
| `return` | Гарантирует неизменность результата, истории и id |
| Нормализация двух операндов | Нужна для человекочитаемого `expression` после уже успешной проверки |
| `createHistoryEntry` | Использует текущий id и проверенный результат |
| `nextHistoryIdRef.current += 1` | Выполняется только для созданной успешной записи |
| Функциональный `setHistory` | Получает актуальный previous state |
| `setErrorMessage('')` | Снимает старую ошибку после успеха |
| `setResultMessage(...)` | Публикует новый успешный результат |

### 8.4. Почему пустая история рендерится отдельно

Текущий код использует условный рендер, а не `ListEmptyComponent`. Это делает учебную ветку явной: либо доступный текст `Empty history message`, либо `FlatList` с меткой `Calculation history`. Оба подхода возможны, но тесты и документация соответствуют текущему.

### 8.5. Что проверяют компонентные тесты сверх чистых функций

Они подтверждают, что:

- labels действительно находят поля;
- роли и имена находят кнопки;
- `fireEvent.changeText` меняет управляемый state;
- `fireEvent.press` доходит до обработчика;
- `FlatList.props.data` имеет правильный порядок;
- `keyExtractor` выдаёт `history-1`, `history-2`, `history-3`;
- ошибка переполнения не изменяет UI-контракт;
- после ошибки следующий успех использует id без пропуска.

## 12. Вопросы и полные ответы

1. **Почему `firstInput` и `secondInput` начинаются с пустой строки?**  
   `TextInput` работает с текстом. Пустая строка точно представляет ещё не введённое значение и позволяет валидатору отличить отсутствие числа от нуля.

2. **Почему преобразование выполняется при нажатии, а не на каждом символе?**  
   Во время набора существуют промежуточные строки, например `-` или `,`. Хранение текста не мешает печати, а проверка в момент команды даёт единый предсказуемый результат.

3. **Что означает управляемый `TextInput`?**  
   Его отображаемое `value` приходит из state, а каждое `onChangeText` просит React записать новую строку через setter. Источником истины остаётся state.

4. **Что разрешает регулярное выражение?**  
   Необязательный `+` или `-`, затем либо цифры с необязательной дробной частью, либо дробный разделитель и цифры. Разделитель — одна точка или одна запятая.

5. **Зачем после regex нужен `Number.isFinite`?**  
   Regex проверяет форму, а числовая проверка защищает диапазон JavaScript `Number`. Эти проверки отвечают на разные вопросы.

6. **Почему проверяется конечность результата?**  
   Два операнда могут быть конечными, но операция над очень большими значениями может переполнить диапазон и дать `Infinity`.

7. **Что делает ранний `return`?**  
   Завершает обработчик после установки ошибки. Код создания записи, увеличения id и обновления успешного результата не выполняется.

8. **Почему операнды нормализуются ещё раз в `handleCalculation`?**  
   `calculateValues` возвращает только итоговое значение. После успешной проверки обработчику нужны числовые операнды для человекочитаемого `expression`; повторная конверсия безопасна, потому что тексты уже признаны валидными.

9. **Почему `formatNumber` вызывает `toFixed(10)`?**  
   Это сокращает обычный двоичный шум вроде `0.30000000000000004`. Повторный `Number` убирает незначащие нули, а `String` готовит отображение.

10. **Почему `appendHistory` не использует `push`?**  
    React state считается неизменяемым. Новый массив получает новую ссылку, не повреждает предыдущую версию и корректно воспринимается `FlatList`.

11. **Почему используется updater-функция `previous => ...`?**  
    Новая история зависит от предыдущей. React может ставить обновления в очередь, и updater получает актуальное ожидающее значение.

12. **Почему `nextHistoryIdRef` не является обычной локальной переменной?**  
    Обычная переменная внутри `App` создавалась бы заново при каждом рендере. Ref сохраняет `current` на всём времени жизни смонтированного компонента.

13. **Почему счётчик не лежит в state?**  
    Сам счётчик не показывается. Изменение state вызвало бы рендер, который не нужен только ради выдачи id.

14. **Почему дубликаты безопасны?**  
    `expression` может совпадать, но `id` увеличивается на каждом успехе. `keyExtractor` возвращает уникальный id.

15. **Почему `FlatList` получает новый массив?**  
    `FlatList` сравнивает props по ссылкам. Неизменяемое обновление меняет ссылку `data` и позволяет списку увидеть новую запись.

16. **Зачем `accessibilityLiveRegion="polite"`?**  
    На Android это просит сервис доступности объявить изменение, не прерывая текущее чтение немедленно.

17. **Почему у результата и ошибки нет `accessibilityLabel`?**  
    Их собственный текст уже является актуальным доступным содержимым. Статическая метка могла бы скрыть изменившееся значение; `testID` используется отдельно только для теста.

18. **Что происходит после полного перезапуска?**  
    Компонент монтируется заново: state получает начальные значения, `history` становится `[]`, а `nextHistoryIdRef.current` — `1`. Постоянного хранилища нет.

Это самостоятельный учебный проект Expo/React Native. Он соответствует первому заданию: принимает два числа, складывает или вычитает их и показывает результат. Проект не зависит от остальных трёх приложений комплекта.

## 1. Оригинальное требование и перевод

Оригинал задания:

> Create simple React Native calculator app which contains:
> - Two TextInput components with numeric keyboard.
> - Two Button components for calculating sum and subtraction. When the buttons are pressed the calculated answer is shown in the Text component.

Перевод:

> Создайте простое приложение-калькулятор на React Native. В нём должны быть два компонента `TextInput` с числовой клавиатурой и две кнопки для сложения и вычитания. После нажатия кнопки вычисленный ответ должен отображаться в компоненте `Text`.

Главная учебная цель — понять путь данных: пользователь вводит текст → React сохраняет его в state → обработчик кнопки проверяет и преобразует значения → React обновляет результат → компонент перерисовывается.

## 2. Реализованные критерии

- Два управляемых компонента `TextInput`.
- Для обоих полей задан `keyboardType="numeric"`.
- Кнопка `+` складывает значения.
- Кнопка `-` вычитает второе значение из первого.
- Результат выводится в `Text` как `Result: ...`.
- Принимаются целые, отрицательные и дробные числа.
- Поддерживаются точка и запятая как десятичный разделитель.
- Шестнадцатеричная и экспоненциальная запись (`0x10`, `1e2`) намеренно отклоняются: задание работает с обычным десятичным вводом.
- Пустая строка, обычный текст и бесконечность не превращаются в `NaN` на экране.
- При ошибке отображается `Enter a valid number.`.
- Переполнение результата отклоняется сообщением `Result is too large.`.
- Ошибочный ввод не стирает последний правильный результат.
- У полей, результата, сообщения об ошибке и кнопок есть доступные подписи.
- Логика вычислений вынесена из интерфейса и покрыта unit-тестами.
- Поведение экрана покрыто UI-тестами.

## 6. State, props и события

В `App.js` создано четыре состояния:

| State | Начальное значение | Что хранит |
|---|---:|---|
| `firstInput` | `''` | текст первого поля |
| `secondInput` | `''` | текст второго поля |
| `resultMessage` | `'Result:'` | последний корректный результат |
| `errorMessage` | `''` | текст текущей ошибки |

Пример управляемого поля:

```jsx
<TextInput
  onChangeText={setFirstInput}
  value={firstInput}
/>
```

`value` берётся из state. Событие `onChangeText` получает новую строку и вызывает setter. После setter React снова вызывает компонент и показывает новое значение.

Кнопка передаёт обработчику выбранную операцию:

```jsx
<Button onPress={() => handleCalculation('+')} title="+" />
```

`props` — входные параметры компонента. Например, `title`, `onPress`, `style`, `value` и `accessibilityLabel` являются props. State отличается тем, что принадлежит экземпляру `App` и меняется через setter.

## 7. Подробный разбор алгоритма

Алгоритм одного нажатия:

1. Пользователь вводит две строки.
2. `onChangeText` сохраняет строки в `firstInput` и `secondInput`.
3. Нажатие `+` или `-` вызывает `handleCalculation(operation)`.
4. Обработчик вызывает `calculateValues`.
5. `calculateValues` дважды вызывает `parseNumberInput`.
6. `parseNumberInput` удаляет пробелы по краям и заменяет запятую точкой.
7. `Number(...)` выполняет явное преобразование строки.
8. `Number.isFinite(...)` отклоняет `NaN`, `Infinity` и `-Infinity`.
9. При ошибке изменяется только `errorMessage`; старый результат остаётся.
10. При успехе ошибка очищается, число форматируется и записывается в `resultMessage`.
11. React перерисовывает только то, что зависит от изменённого state.

Ключевой фрагмент:

```js
const calculation = calculateValues(firstInput, secondInput, operation);

if (!calculation.ok) {
  setErrorMessage(calculation.error);
  return;
}

setErrorMessage('');
setResultMessage(`Result: ${formatNumber(calculation.value)}`);
```

Ранний `return` не позволяет выполнить строки успешного сценария после ошибки.

`formatNumber` использует `toFixed(10)`, а затем снова `Number`, чтобы в простых учебных примерах не показывать артефакт двоичной арифметики вроде `0.30000000000000004` и одновременно убрать лишние нули.

## 8. Основные понятия для объяснения ученицей

**Компонент** — функция, возвращающая JSX. `App` является корневым компонентом экрана.

**JSX** — синтаксис, похожий на HTML, из которого React создаёт дерево нативных компонентов.

**State** — данные компонента, изменение которых вызывает новый render.

**Hook `useState`** — функция, создающая значение state и setter:

```js
const [firstInput, setFirstInput] = useState('');
```

**Событие** — действие пользователя. Здесь используются `onChangeText` и `onPress`.

**Управляемый ввод** — `TextInput`, значение которого определяется state через `value`.

**Иммутабельность** — старое значение state напрямую не изменяется. Мы передаём setter новое значение.

**Чистая функция** — функция, результат которой зависит только от аргументов. `parseNumberInput`, `calculateValues` и `formatNumber` не используют state интерфейса.

**Условный сценарий** — ветвление `if (!calculation.ok)`, разделяющее ошибку и успех.

## 11. Типичные ошибки и исправления

| Ошибка | Симптом | Причина | Исправление |
|---|---|---|---|
| Строки складываются | `2 + 3` даёт `23` | `TextInput` возвращает строки | Явно вызвать `Number` после проверки |
| Пустое поле даёт `0` | результат выглядит допустимым | `Number('') === 0` | Проверить `normalized === ''` до вычисления |
| На экране `NaN` | неверный текст преобразован без проверки | отсутствует `Number.isFinite` | отклонять нечисловое значение |
| Вычитание наоборот | `23 - 12` даёт `-11` | перепутан порядок операндов | использовать `first - second` |
| Результат не меняется | кнопка ничего не делает | в `onPress` передана не функция | `onPress={() => handleCalculation('+')}` |
| Функция вызывается при render | вычисление происходит сразу | написано `onPress={handleCalculation('+')}` | обернуть вызов в стрелочную функцию |
| Поле нельзя редактировать | `value` задан, setter отсутствует | управляемый ввод неполный | добавить `onChangeText={setFirstInput}` |
| Старый результат исчезает при ошибке | setter результата вызывается слишком рано | смешаны ветки ошибки и успеха | сделать ранний `return` |
| Metro не открывает Android | эмулятор не запущен или ADB его не видит | отсутствует активное устройство | запустить AVD и проверить `adb devices` |
| `EBADENGINE` | предупреждение о React Native 0.81 | Node ниже 20.19.4 | обновить Node и снова выполнить `npm ci` |
| На экране `Infinity` после огромных чисел | результат переполнил диапазон JavaScript | проверены входы, но не итог операции | проверить `Number.isFinite(value)` после вычисления |

## 12. Вопросы преподавателя

1. Почему значения `TextInput` хранятся как строки?
2. Что возвращает `useState`?
3. Чем `value` отличается от `onChangeText`?
4. Когда вызывается `handleCalculation`?
5. Почему нельзя написать `onPress={handleCalculation('+')}`?
6. Где строка превращается в число?
7. Зачем сначала проверять пустую строку?
8. Для чего нужен `Number.isFinite`?
9. Почему вычисления вынесены в `src/calculator.js`?
10. Что произойдёт после вызова setter?
11. Почему при ошибке используется ранний `return`?
12. Как добавить умножение без копирования всей логики?

## 13. Модельные ответы

1. `TextInput` по контракту передаёт текст; даже числовая клавиатура не меняет тип данных.
2. Текущее значение state и функцию для его обновления.
3. `value` задаёт показанное значение, а `onChangeText` обрабатывает новый текст пользователя.
4. После нажатия одной из кнопок, потому что функция передана в `onPress` через стрелочную функцию.
5. Такая запись вызовет функцию во время render и передаст в `onPress` её результат, а не обработчик.
6. В `parseNumberInput` через `Number(normalized)`.
7. JavaScript считает `Number('')` равным нулю, но по условию пустое поле должно быть ошибкой.
8. Чтобы отсеять `NaN`, `Infinity` и `-Infinity`.
9. Чистую логику проще понимать, переиспользовать и тестировать без интерфейса.
10. React запланирует обновление state и снова выполнит компонент с новым значением.
11. Чтобы после ошибки не выполнялась успешная ветка и не менялся последний корректный результат.
12. Разрешить операцию `'*'`, добавить соответствующую ветку вычисления, кнопку и тесты.

Короткая формула защиты: «Ввод хранится как строка, по событию кнопки проходит валидацию и преобразование, а setter обновляет отображаемый результат».

## 14. Мини-защита на английском

Готовый рассказ:

> This is a simple calculator built with React Native and Expo. It has two controlled TextInput components and two Button components. The input is stored as text until the button event. When the user presses a button, the app validates both values, converts them to numbers and performs addition or subtraction. The result changes only after valid input. Invalid input shows an error and keeps the previous valid result. I separated the calculation logic from the user interface, so it can be tested independently.

Полезные фразы:

- `The input is stored as text until the button event.` — Ввод хранится как текст до события кнопки.
- `The result changes only after valid input.` — Результат меняется только после корректного ввода.
- `This state stores the first input value.` — Это состояние хранит первое введённое значение.
- `The onChangeText event updates the state.` — Событие `onChangeText` обновляет состояние.
- `The onPress event calls the calculation handler.` — Событие `onPress` вызывает обработчик вычисления.
- `I validate both fields before calculating.` — Я проверяю оба поля перед вычислением.
- `The calculation logic is a pure function.` — Логика вычисления является чистой функцией.

Возможный вопрос и ответ:

> **Why do you keep the inputs as strings?**  
> React Native TextInput returns strings. I convert them only when the user starts a calculation, because an unfinished input is still valid while the user is typing.

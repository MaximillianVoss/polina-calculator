# Описание проекта 01 — Calculator

## 1. Карточка проекта

| Параметр | Значение |
|---|---|
| Папка | `projects/01-calculator` |
| Тип | самостоятельное приложение Expo/React Native |
| Назначение | сложение и вычитание двух введённых чисел |
| Уровень | первое знакомство с React Native |
| Основные темы | JSX, компоненты, state, события, управляемый ввод, валидация |
| Точка входа | `index.js` → `App.js` |
| Предметная логика | `src/calculator.js` |
| Автоматические проверки | `__tests__/App.test.js`, `__tests__/calculator.test.js` |
| Проверенная платформа | Android Emulator через Expo Go |

Проект является законченной обязательной работой, а не фрагментом второго
калькулятора. Его можно копировать, устанавливать и запускать отдельно.

## 2. Условие задания и перевод

Оригинальное условие со скриншота:

> Create simple React Native calculator app which contains:
>
> - Two TextInput components with numeric keyboard.
> - Two Button components for calculating sum and subtraction. When the
>   buttons are pressed the calculated answer is shown in the Text component.

Перевод:

> Создайте простое приложение-калькулятор на React Native. В нём должны быть
> два компонента `TextInput` с числовой клавиатурой и два компонента `Button`
> для вычисления суммы и разности. После нажатия кнопки вычисленный ответ
> должен отображаться в компоненте `Text`.

Обязательное ядро задания — два поля, две операции и видимый результат.
Проверка ошибочного ввода, поддержка десятичной запятой и тесты добавлены как
учебное усиление, не меняющее смысл работы.

## 3. Результаты обучения

После самостоятельного разбора ученица должна уметь:

1. Объяснить, почему `TextInput` передаёт строку даже при числовой клавиатуре.
2. Создать state через `useState` и обновить его setter-функцией.
3. Связать `value` и `onChangeText`, получив управляемый ввод.
4. Передать функцию в `onPress`, не вызывая её во время рендера.
5. Преобразовать проверенную строку в число.
6. Разделить интерфейс и чистую предметную логику.
7. Показать успешный результат и отдельную ошибку.
8. Объяснить повторный рендер после изменения state.
9. Запустить приложение через Metro и Expo Go.
10. Проверить обязательные сценарии вручную и через Jest.

## 4. Функциональные критерии

| Критерий | Реализация | Как проверить |
|---|---|---|
| Два поля | два управляемых `TextInput` | видны подписи `First number` и `Second number` |
| Числовая клавиатура | `keyboardType="numeric"` | нажать на каждое поле на устройстве |
| Сложение | `handleCalculation('+')` | `23` и `12` дают `Result: 35` |
| Вычитание | `handleCalculation('-')` | `23` и `12` дают `Result: 11` |
| Вывод результата | `Text` с `testID="result-message"` | результат изменяется после кнопки |
| Проверка ввода | `parseNumberInput` | пустая строка и `abc` дают ошибку |
| Дробные числа | точка и запятая | `2,5 + 1.25` даёт `3.75` |
| Сохранение результата при ошибке | ранний `return` | после верного результата очистить одно поле |
| Защита от переполнения | `Number.isFinite(value)` | два огромных числа дают `Result is too large.` |

## 6. Архитектура и зоны ответственности

| Часть | Ответственность | Чего она не делает |
|---|---|---|
| `index.js` | регистрирует `App` в Expo | не содержит расчётов |
| `App.js` | хранит UI-state, отображает экран, принимает события | не разбирает числовую грамматику самостоятельно |
| `src/calculator.js` | проверяет строки, вычисляет и форматирует | не импортирует React Native и не меняет state |
| `App.test.js` | имитирует ввод и нажатия пользователя | не запускает Android Emulator |
| `calculator.test.js` | проверяет чистые функции и границы | не проверяет расположение компонентов |

Схема выполнения:

```text
TextInput
   ↓ onChangeText
firstInput / secondInput
   ↓ onPress
handleCalculation(operation)
   ↓
calculateValues(...)
   ↓ success                 ↓ error
setResultMessage(...)        setErrorMessage(...)
   ↓                             ↓
повторный render → Text на экране
```

## 7. Модель состояния

| State | Начальное значение | Изменяется когда | Используется где |
|---|---|---|---|
| `firstInput` | `''` | пользователь меняет первое поле | первое `TextInput`, расчёт |
| `secondInput` | `''` | пользователь меняет второе поле | второе `TextInput`, расчёт |
| `resultMessage` | `'Result:'` | расчёт завершился успешно | синий блок результата |
| `errorMessage` | `''` | ввод ошибочен или снова корректен | красная строка ошибки |

State не изменяется прямым присваиванием. Запись
`firstInput = '23'` была бы ошибочной; React получает новое значение через
`setFirstInput('23')`.

## 8. Поток данных и событий

Пример для `23 + 12`:

1. `onChangeText={setFirstInput}` получает строку `'23'`.
2. React сохраняет её в `firstInput` и перерисовывает поле.
3. Второе поле аналогично сохраняет `'12'`.
4. Кнопка `+` вызывает `() => handleCalculation('+')`.
5. Обработчик передаёт обе строки в `calculateValues`.
6. `parseNumberInput` подтверждает обычную десятичную запись.
7. Строки преобразуются в числа `23` и `12`.
8. Чистая функция возвращает `{ ok: true, value: 35 }`.
9. `formatNumber` создаёт строку `'35'`.
10. `setResultMessage('Result: 35')` планирует новый рендер.
11. Компонент `Text` показывает новый результат.

Данные идут вниз в JSX через props, события поднимают новые значения в
обработчики, а setter запускает новый рендер.

## 9. Алгоритмы предметной логики

### 9.1 Разбор числа

```js
const decimalPattern = /^[+-]?(?:\d+(?:[.,]\d+)?|[.,]\d+)$/;
```

Регулярное выражение разрешает знак, цифры и один десятичный разделитель.
После проверки запятая заменяется точкой, потому что JavaScript ожидает точку:

```js
const value = Number(trimmed.replace(',', '.'));
```

### 9.2 Выбор операции

```js
const value =
  operation === '+'
    ? first.value + second.value
    : first.value - second.value;
```

В текущем интерфейсе обработчик получает только `'+'` или `'-'`.

### 9.3 Форматирование

```js
export function formatNumber(value) {
  return String(Number(value.toFixed(10)));
}
```

Это превращает `0.1 + 0.2` в учебно ожидаемое `0.3` и убирает лишние нули.

## 10. Валидация и ошибочные сценарии

| Ввод/ситуация | Результат | Почему |
|---|---|---|
| `''` или пробелы | `Enter a valid number.` | пустое поле не считается нулём |
| `abc` | та же ошибка | строка не соответствует десятичной грамматике |
| `0x10` | та же ошибка | шестнадцатеричная запись не входит в задание |
| `1e2` | та же ошибка | экспоненциальная запись намеренно запрещена |
| `2.3.4` | та же ошибка | более одного разделителя |
| `2,5` | число `2.5` | запятая поддерживается для удобства |
| два числа порядка `10^308` | `Result is too large.` | результат стал бесконечностью |

При ошибке `handleCalculation` выполняет ранний `return`. Поэтому последний
успешный `resultMessage` не затирается ошибочным вычислением.

## 11. Запуск с нуля на Windows и macOS

### 11.1 Общая подготовка

Нужен Node.js не ниже `20.19.4`. Проект проверен на Node 24.

```powershell
node --version
npm --version
```

Откройте именно готовую папку `01-calculator`: версии Expo и React уже
зафиксированы в `package-lock.json`.

```powershell
Set-Location "путь\к\react-native-homework-kit\projects\01-calculator"
npm ci
npx expo start
```

### 11.2 Windows + Android Studio

1. В Android Studio откройте **Tools → Device Manager**.
2. Запустите виртуальный Pixel и дождитесь экрана Android.
3. В терминале VS Code выполните `npx expo start`.
4. В меню Metro нажмите `a`.
5. Expo Go откроет приложение на виртуальном телефоне.

Прямая команда при уже запущенном эмуляторе:

```powershell
npm run android
```

### 11.3 macOS + iOS Simulator

1. Установите Xcode и iOS Simulator runtime.
2. Откройте Terminal в папке проекта.
3. Выполните `npm ci`, затем `npx expo start`.
4. В меню Metro нажмите `i`.

```bash
cd "/path/to/react-native-homework-kit/projects/01-calculator"
npm ci
npx expo start
```

`i` открывает Simulator, но не используется для редактирования кода в Xcode.
Код по-прежнему удобно писать в VS Code.

### 11.4 Общая схема запуска

```text
App.js → Metro → JavaScript bundle → Expo Go → Emulator/Simulator
```

Автоматические команды:

```powershell
npm test -- --runInBand
```

## 13. Ограничения

- Есть только сложение и вычитание.
- Результат и ввод не сохраняются после перезапуска.
- Нет истории вычислений — она реализуется в проекте 02.
- Нет навигации, сервера, базы данных и авторизации.
- `toFixed(10)` подходит учебным примерам, но не финансовым расчётам.
- iOS-конфигурация присутствует, однако фактическая локальная проверка комплекта
  выполнялась на Android.

## 14. Краткая защита проекта

### На русском

«Приложение содержит два управляемых `TextInput` и две кнопки. Текст полей
хранится в state. После `onPress` обработчик проверяет обе строки, преобразует
их в числа и вызывает сложение или вычитание. При успехе setter обновляет
`resultMessage`, а React повторно отображает компонент. Ошибка выводится
отдельно и не удаляет последний правильный результат. Чистая логика вынесена
из `App.js`, поэтому она тестируется без эмулятора».

### In English

> The app has two controlled TextInput components and two operation buttons.
> Input values stay as strings while the user is typing. A button event
> validates and converts both values, performs addition or subtraction, and
> updates the result state. Invalid input shows an error without deleting the
> previous valid result. The calculation logic is separated from the screen,
> so it can be tested independently.

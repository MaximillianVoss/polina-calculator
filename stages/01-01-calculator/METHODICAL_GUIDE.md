# Методические указания к проекту 01 — Calculator

## 1. Аудитория и предварительные знания

Материал рассчитан на ученицу, которая только начинает React Native, но уже
знает базовые конструкции JavaScript: переменные, функции, `if`, строки,
числа и простые объекты.

До занятия достаточно уметь:

- открыть папку в VS Code;
- выполнить команду в Terminal/PowerShell;
- прочитать простую стрелочную функцию;
- различить строку `'23'` и число `23`;
- сохранить файл.

Не требуется заранее знать hooks, JSX, Expo, Metro или устройство React state.

## 7. Пошаговое программирование

Этот раздел используется, если приложение воспроизводится с пустого
`App.js`. После каждого шага проект должен снова запускаться.

### Шаг 1. Импорты

```js
import { useState } from 'react';
import { Button, StyleSheet, Text, TextInput, View } from 'react-native';
import { StatusBar } from 'expo-status-bar';

import { calculateValues, formatNumber } from './src/calculator';
```

Вопрос: «Почему `useState` импортируется из `react`, а `TextInput` — из
`react-native`?» Ответ: hook управляет React-состоянием, а `TextInput` является
нативным UI-компонентом React Native. Отдельный локальный импорт подключает
чистые функции предметной логики, которые понадобятся обработчику на шаге 6.

### Шаг 2. Минимальный компонент

```jsx
export default function App() {
  return (
    <View>
      <Text>Calculator</Text>
    </View>
  );
}
```

Проверьте, что экран отображается, до добавления логики.

### Шаг 3. State

```js
const [firstInput, setFirstInput] = useState('');
const [secondInput, setSecondInput] = useState('');
const [resultMessage, setResultMessage] = useState('Result:');
const [errorMessage, setErrorMessage] = useState('');
```

Ученица подписывает слева значение, справа setter, в скобках начальное
значение.

### Шаг 4. Управляемые поля

```jsx
<TextInput
  accessibilityLabel="First number"
  keyboardType="numeric"
  onChangeText={setFirstInput}
  value={firstInput}
/>
```

Затем ученица создаёт второе поле по тому же принципу, меняя имена state.

### Шаг 5. Результат и ошибка

```jsx
<Text testID="result-message">{resultMessage}</Text>
<Text testID="error-message">{errorMessage}</Text>
```

Фигурные скобки переключают JSX из текста в JavaScript-выражение.

### Шаг 6. Обработчик

```js
function handleCalculation(operation) {
  const calculation = calculateValues(firstInput, secondInput, operation);

  if (!calculation.ok) {
    setErrorMessage(calculation.error);
    return;
  }

  setErrorMessage('');
  setResultMessage(`Result: ${formatNumber(calculation.value)}`);
}
```

Перед запуском попросите ученицу пальцем показать ветку ошибки и ветку успеха.

### Шаг 7. Кнопки

```jsx
<Button onPress={() => handleCalculation('+')} title="+" />
<Button onPress={() => handleCalculation('-')} title="-" />
```

Контрольный вопрос: «Что случится без `() =>`?» — обработчик будет вызван во
время рендера, а `onPress` не получит нужную функцию.

### Шаг 8. Стили и проверка

Добавляйте стили после рабочего поведения. После каждого логического блока
проверяйте `23 + 12`, а в конце запускайте весь Jest.

## 11. Диагностика типичных ошибок

| Симптом | Диагностический вопрос | Причина | Исправление |
|---|---|---|---|
| `2 + 3` показывает `23` | «Какой тип пришёл из поля?» | сложены строки | преобразовать после проверки |
| поле не редактируется | «Есть ли `onChangeText`?» | задан `value`, но нет setter | связать оба props |
| расчёт происходит сразу | «Что лежит в `onPress`?» | функция вызвана при render | передать стрелочную функцию |
| виден `NaN` | «Где проверяется результат Number?» | нет валидации | применить строгий разбор |
| ошибка стирает результат | «Вызывается ли setter результата после ошибки?» | нет раннего выхода | добавить `return` |
| `23 - 12` даёт `-11` | «Каков порядок операндов?» | выполнено `second - first` | использовать `first - second` |
| Metro не видит устройство | «Запущен ли эмулятор?» | AVD/Simulator не готов | сначала запустить устройство |
| `EBADENGINE` | «Какая версия Node?» | Node ниже `20.19.4` | обновить Node и открыть новый терминал |

## 12. Контрольные вопросы и модельные ответы

1. **Почему ввод хранится строкой?**  
   `TextInput` передаёт текст. Числовая клавиатура меняет удобство ввода, но не
   JavaScript-тип значения.

2. **Что возвращает `useState('')`?**  
   Текущее значение state и setter-функцию для запроса обновления.

3. **Что делает `value={firstInput}`?**  
   Указывает, что отображаемое значение поля берётся из React state.

4. **Что делает `onChangeText={setFirstInput}`?**  
   Передаёт новую строку setter-функции при изменении текста.

5. **Почему `onPress={() => handleCalculation('+')}`?**  
   `onPress` должен получить функцию, которую React Native вызовет после
   нажатия. Стрелка также передаёт знак операции.

6. **Где строка становится числом?**  
   В `parseNumberInput`, после проверки регулярным выражением, через `Number`.

7. **Зачем нужен `Number.isFinite` дважды?**  
   Сначала он защищает преобразованное значение, затем результат операции от
   переполнения.

8. **Что делает ранний `return`?**  
   Завершает обработчик ошибки до очистки ошибки и изменения результата.

9. **Почему логика вынесена в `src/calculator.js`?**  
   Чистые функции проще тестировать и объяснять независимо от Android/iOS UI.

10. **Что происходит после setter?**  
    React планирует обновление state и повторно выполняет компонент с новыми
    значениями.

11. **Почему нельзя менять state через присваивание?**  
    React не получит корректного запроса на обновление и не сможет управлять
    жизненным циклом рендера.

12. **Чем unit-тест отличается от UI-теста?**  
    Unit-тест вызывает чистую функцию, а UI-тест рендерит `App`, вводит текст и
    нажимает кнопку.
